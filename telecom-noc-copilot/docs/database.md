# PostgreSQL (local Docker and AWS RDS)

The FastAPI backend uses one SQLAlchemy 2.x stack for both local Docker PostgreSQL and AWS RDS. Switch environments by changing environment variables only. Do not put credentials in source code.

When `DATABASE_URL` is unset (or `DATABASE_DISABLED=true`), mock OSS APIs keep reading the synthetic JSON files under `data/`. Tickets, equipment, and topology always stay on JSON; they are not part of the ten relational tables.

## Prerequisites

- Python 3.11+
- Docker Engine with Compose v2
- A copy of `.env.example` saved as `.env` (never commit `.env`)

```bash
cd telecom-noc-copilot
cp .env.example .env
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
```

## Local Docker PostgreSQL

Expected URL:

```text
DATABASE_URL=postgresql+psycopg://noc_user:local_dev_password@localhost:5432/telecom_noc
```

Start, inspect, and stop **without** deleting the volume:

```bash
cd telecom-noc-copilot
docker compose up -d postgres
docker compose ps
docker logs telecom-noc-postgres
docker compose stop postgres
```

Do not use `docker compose down -v` as routine cleanup. That flag deletes `telecom_noc_postgres_data` and all rows.

## Connection verification

```bash
cd telecom-noc-copilot/backend
python -c "from app.db.session import check_database; print(check_database())"
# After the API is running:
# GET /health           -> database=ok|disabled|unavailable (always HTTP 200)
# GET /health/ready     -> HTTP 503 when DATABASE_URL is set but PostgreSQL is down
```

## Migrations (Alembic)

Schema changes are applied only by Alembic. Importing application modules does not create tables.

Fresh database:

```bash
cd telecom-noc-copilot/backend
alembic upgrade head
alembic current
```

Generate a future revision after model changes:

```bash
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

The initial revision is `20261028_01` (`create telecom noc tables`). Review autogenerated SQL before applying it. Never drop production tables as a workaround.

## Seed data

```bash
cd telecom-noc-copilot/backend
python -m app.db.seed --counts
```

Equivalent wrapper: `python ../scripts/seed_database.py`. Re-runs upsert on public IDs and do not duplicate rows. Remediation actions are `proposed` or `pending` only.

## Tests

JSON/API tests (no PostgreSQL required):

```bash
cd telecom-noc-copilot/backend
pytest -q
```

PostgreSQL tests need an **isolated** database. Never use shared or production RDS:

```bash
# Create telecom_noc_test in the local Docker instance, then:
set TEST_DATABASE_URL=postgresql+psycopg://noc_user:local_dev_password@localhost:5432/telecom_noc_test
pytest -q -m postgres
```

Skip those tests with `pytest -q -m "not postgres"` (they skip automatically when `TEST_DATABASE_URL` is unset).

## AWS RDS PostgreSQL

1. Create a private RDS for PostgreSQL instance. Do **not** make it publicly accessible from this application.
2. Place the backend on a network path that can reach RDS (typically the same VPC, or a peered VPC) and allow the backend security group on port 5432 of the RDS security group.
3. Store the username, password, host, port, and database name in AWS Secrets Manager. Grant the task role `secretsmanager:GetSecretValue` on that secret.
4. Set:

```text
DATABASE_SECRET_ARN=arn:aws:secretsmanager:region:account:secret:name
AWS_REGION=us-east-1
DATABASE_SSL_MODE=verify-full
DATABASE_SSL_ROOT_CERT=/path/to/rds-combined-ca-bundle.pem
```

Or set `DATABASE_URL` from a secrets injection step at deploy time. Prefer Secrets Manager in deployed environments. `boto3` is required only when `DATABASE_SECRET_ARN` is set.

5. Do not disable TLS verification (`sslmode=disable` or `verify-full` without a CA bundle) to work around connection errors.

Switching local Docker vs RDS is a configuration change only. The SQLAlchemy models, sessions, and Alembic migrations are the same.

## ON DELETE behavior

| Child | Parent | ON DELETE |
| --- | --- | --- |
| network_alarms, telemetry_metrics, deployments, incidents | network_sites | RESTRICT |
| incident_alarms, investigation_results, remediation_actions | incidents / network_alarms | RESTRICT |
| runbook_references, audit_events | incidents | SET NULL |

Audit rows and historical operational data are not cascade-deleted.

## Compatibility notes

- Telemetry is stored as wide KPI samples (`latency_ms`, `throughput_mbps`, `utilization_pct`, `dropped_call_rate_pct`) to match `GET /sites/{site_id}/metrics`. That is the existing API contract; an EAV `metric_name`/`value`/`unit` layout would break current clients. Dropped-call rate is the synthetic analog of packet loss in this dataset.
- Tickets, OSS equipment, and topology remain JSON fixtures (not in the ten tables).
- `POST /incidents/{id}/investigate`, `POST /incidents/{id}/approve`, and `GET /incidents/{id}/report` are not implemented. `GET /incidents/{id}` returns the operational `Incident` schema (including `evidence_alarm_ids`). The React investigation workspace still expects a richer payload and will keep using labeled demo data for that view.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `password authentication failed` | `POSTGRES_PASSWORD` in `.env` matches `DATABASE_URL`. Recreate the volume only if you intentionally want an empty database. |
| `connection refused` / `could not translate host name` | Postgres container is healthy (`docker compose ps`). Local URL host is `localhost`, not the container name, when the API runs on the host. |
| RDS timeout | Backend has no route to the subnet. RDS is not public; security group must allow the backend SG on 5432. |
| `SSL SYSCALL error` / certificate verify failed | `DATABASE_SSL_MODE=verify-full` and `DATABASE_SSL_ROOT_CERT` point at the current Amazon RDS CA bundle. Do not set `sslmode=disable`. |
| `DATABASE_SSL_ROOT_CERT is required` | verify-ca / verify-full were set without a CA file. |
| Tests unexpectedly hitting Postgres | Default pytest sets `DATABASE_DISABLED=true`. Postgres tests require `TEST_DATABASE_URL`. |
